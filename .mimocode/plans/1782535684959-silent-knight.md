# Advanced Filtering for Export Workflow

## Goal
Add transaction type, amount range, payment mode, member search, sort order, and active filter badge to the TransactionExportSheet.

## Files to Modify

### 1. `lib/features/transactions/data/services/transaction_export_options.dart`
Add fields to `TransactionExportOptions`:
```dart
final List<TransactionType> typeFilter;     // multi-select
final List<PaymentMode> paymentModes;       // multi-select
final double? amountMin;
final double? amountMax;
final String searchQuery;
final String sortBy;                        // default: 'date_desc'
```
Add `activeFilterCount` getter and `copyWith` method.

### 2. `lib/features/transactions/data/repositories/transactions_repository.dart`
Add to `getTransactionsForExport`:
- `double? amountMin` → `.gte('amount', amountMin)`
- `double? amountMax` → `.lte('amount', amountMax)`
- `String sortBy = 'date_desc'` → dynamic sort (copy from `getTransactionsPaginated`)
- `List<TransactionType>? typeFilters` → `.inFilter('type', ...)` for multi-select

### 3. `lib/features/transactions/presentation/widgets/transaction_export_sheet.dart`
Major UI expansion:
- Add `currentFilter` parameter (TransactionFilter from page)
- Add state fields: `_selectedTypes`, `_selectedPaymentModes`, `_amountMin`, `_amountMax`, `_searchQuery`, `_sortBy`
- Add "Advanced Filters" toggle row with badge
- Add expandable section with:
  - Transaction type chips (EMI, Savings, Disbursed, Withdrawal, Penalty)
  - Amount range (Min/Max fields)
  - Payment mode chips (Cash, UPI, Bank, Cheque, Card)
  - Member search text field
  - Sort dropdown
- Add filter count badge on Generate button
- Update `_generate()` to pass all filters

### 4. `lib/features/transactions/presentation/pages/transactions_page.dart`
- Pass `_filter` as `currentFilter` to `TransactionExportSheet`
- Use export options filters in `_onExport` when period != allFiltered

## Key Design Decisions
- Expandable section via AnimationController + SizeTransition (same as TransactionFilterPanel)
- "All Filtered" uses page's already-loaded `_transactions` (no extra fetch)
- Empty filter lists = pass `null` to repository (no filter applied)
- Amount validation: ignore invalid values via `double.tryParse`
- No debounce needed (user taps Generate, not live search)
