# Push Notification Implementation Plan

## Overview

Implement a complete push notification system for MicroFlow Pro using **Firebase Cloud Messaging (FCM)**. This will enable the app to deliver notifications to users even when the app is closed/backgrounded, addressing the current limitation where notifications only work when the app is open.

---

## Current State Analysis

**What Exists:**
- Local notifications only (APK update prompts on Android)
- In-app notification system for staff (`staff_notifications` table + Supabase Realtime)
- In-app notification system for customers (`customer_notifications` table + Supabase Realtime)
- Smart notification generation logic (EMI reminders, savings milestones, loan approvals)
- Customer notification preferences model with `pushEnabled` toggle (currently unused)
- Email and WhatsApp edge functions already implemented

**What's Missing:**
- Firebase packages (`firebase_core`, `firebase_messaging`)
- Firebase configuration files (no `google-services.json`, `GoogleService-Info.plist`)
- FCM token registration and storage
- Push notification handlers (foreground, background, terminated)
- Server-side edge function to send push notifications via FCM
- Database table for device tokens

### Phase 2: Device Token Management

#### 2.1 Create Device Tokens Table

```sql
CREATE TABLE device_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  org_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  fcm_token TEXT NOT NULL,
  platform TEXT NOT NULL DEFAULT 'android', -- android|ios|web
  device_info JSONB, -- {model, os_version, app_version}
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id, fcm_token)
);

-- RLS policies
ALTER TABLE device_tokens ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can manage their own tokens"
  ON device_tokens FOR ALL
  USING (user_id = auth.uid());

CREATE POLICY "Service role can manage all tokens"
  ON device_tokens FOR ALL
  USING (auth.role() = 'service_role');

-- Index for efficient token lookups
CREATE INDEX idx_device_tokens_user_id ON device_tokens(user_id);
CREATE INDEX idx_device_tokens_org_id ON device_tokens(org_id);
CREATE INDEX idx_device_tokens_active ON device_tokens(is_active) WHERE is_active = true;
```

#### 4.2 Create Notification Trigger Function

**File to create:**
- `supabase/migrations/[timestamp]_notification_trigger.sql`

```sql
-- Database function to trigger push notifications
CREATE OR REPLACE FUNCTION notify_user_push()
RETURNS TRIGGER AS $$
BEGIN
  -- Call send-push-notification edge function
  PERFORM net.http_post(
    url := current_setting('app.settings.supabase_url') || '/functions/v1/send-push-notification',
    headers := jsonb_build_object(
      'Authorization', 'Bearer ' || current_setting('app.settings.service_role_key'),
      'Content-Type', 'application/json'
    ),
    body := jsonb_build_object(
      'user_id', NEW.user_id,
      'title', NEW.title,
      'body', NEW.message,
      'data', jsonb_build_object('type', NEW.type, 'id', NEW.id)
    )
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Trigger on customer_notifications INSERT
CREATE TRIGGER on_customer_notification_created
  AFTER INSERT ON customer_notifications
  FOR EACH ROW
  EXECUTE FUNCTION notify_user_push();

-- Trigger on staff_notifications INSERT
CREATE TRIGGER on_staff_notification_created
  AFTER INSERT ON staff_notifications
  FOR EACH ROW
  EXECUTE FUNCTION notify_user_push();
```

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Token bloat (inactive tokens accumulating) | Clean up tokens on each app launch and on 404 errors |
| Notification permission denied | Graceful fallback to in-app only notifications |
| Background handler not firing on some Android devices | Document battery optimization settings for users |
| Edge function cold start delays | Use Supabase Edge Function warm-up or queue notifications |
